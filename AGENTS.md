# JeopardyLM — Agent Notes

## Project

Interactive, customizable Jeopardy-style quiz game built with Next.js 13 (static export), React, and TypeScript. Deployed as a static site on Kale Deploy (Cloudflare Workers for Platforms).

## Build

```bash
npm install
npm run build   # next build → outputs static files to ./out/
```

The build uses `output: 'export'` in `next.config.js`, so `next build` generates a fully static site in `./out/`. No server-side rendering at request time.

## Deploy target

- **Platform**: Kale Deploy (Cloudflare Workers for Platforms)
- **URL**: https://jeopardy-lm.cuny.qzz.io
- **Shape**: `static_site` — no request-time Worker logic
- **Assets**: `./out` (generated by `npm run build`)

## Key files

| File | Purpose |
|------|---------|
| `src/JeopardyGame.tsx` | Main game component — all game state and UI |
| `src/AISettingsModal.tsx` | AI provider config and question generation |
| `src/jeopardyDefaults.ts` | Default board content |
| `styles/globals.css` | All CSS (Tailwind + custom) |
| `pages/index.tsx` | Next.js entry page |

## Constraints

- All game logic is client-side; API keys are stored in browser localStorage
- No server-side routes are used in the deployed build
- `better-sqlite3`, `bcryptjs`, and `jsonwebtoken` are legacy dependencies not used by Next.js pages
- Do not add server-side logic that requires a persistent process
